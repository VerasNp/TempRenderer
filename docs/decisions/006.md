# ADR-006: API gráfica e como lidar com SO

## Contexto

A render vai ser construída acima de alguma biblioteca de interface de hardware. Além disso é necessário escolher como será resolvido o problema de trabalhar com contextos, pedir para o SO desenhar uma Janela, coisa que a API gráfica em sí não se responsabiliza

## A ser considerado

- OpenGL: Portável e muito utilizado;
- Vulkan: Biblioteca low-level permite programadores enviar batches e GPGPU computa diretamente na GPU como sendo uma lista de comandos

## Decisão

Visando uma facilidade de início optamos pelo uso da OpenGL com auxilio do GLFW.

> O GLFW é uma plataforma agnóstica para trabalharmos com janelas. Dado isso ainda podemos trabalhar com a mesma sendo ambiente Windows, Linux ou Apple.
>
> Um exemplo de sua versatilidade é que a GLFW foi desenhada para criar um contexto OpenGL quando uma janela fosse criada, para mudar isso basta usar `glfwWindowHint(GLFW_CLIENT_API, GLFW_NO_API);`

além de ser aquela mais comumente escolhida para o projeto da disciplina. Além disso será utilizado GLAD para auxiliar no trabalho de recuperar a localização das funções específicas implementadas pelo fabricante do driver da placa gráfica que precisa e armazená-los em ponteiros de função para uso posterior. Recuperar esses locais é específico do sistema operacional.

## Consequências

- Portabilidade: Diferentemente de DirectX podemos acabar se adequando a diferentes plataformas;
- Abstração: OpenGL oferece muitas decisões já tomadas, o que seria diferente caso fosse o caso de escolher algo como Vulkan
