### Versionamento

O uso do git flow em sua totalidade com a existência de uma branch dev acabou sendo descartada dado que pela experiência o tamanho da equipe não justificaria a existência de tal, contudo algumas outras branches ainda existirão:

- `main`: código testado e "em produção reside"
- `feat/issue-<numero>`: o desenvolvimento será guiado por issues, assim normalmente elas existirão a partir da branch `main`, ao término será aberto uma Pull Request para merge;
- `hotfix/issue-<numero>`: branch destinada a bugs encontrado em produção de código já mergiado na `main`

Outra parte do versionamento será a utilização de commits baseados nos [conventional commits](https://medium.com/linkapi-solutions/conventional-commits-pattern-3778d1a1e657), uma forma prática de organizar e estruturar mensagens de commits.
